# Gemini Code Review Guide Line

**IMPORTANT: ALL RESPONSES MUST BE IN KOREAN.**
**중요: 모든 리뷰 응답과 요약은 반드시 한국어로만 작성하세요.**

## 1. 기본 원칙

- **응답 언어:** 모든 리뷰, 요약, 개선 제안은 반드시 **한국어**로 작성한다.
- **말투:** 정중하면서도 명확한 기술적 조언을 제공하는 개발 동료의 톤을 유지한다.
- **전문 용어:** 개발자 사이에서 통용되는 전문 용어(예: 컴포넌트, 의존성 주입, 훅 등)는 그대로 사용하되, 설명은 한국어로 상세히 한다.

## 2. 프론트엔드 (Next.js) 지침

- **컴포넌트 구조:** Client Component와 Server Component의 분리가 적절한지 확인한다. 가급적 데이터 페칭은 Server Component에서 수행하도록 권장한다.
- **성능 최적화:** 이미지 최적화(next/image), 불필요한 리렌더링 발생 여부, 그리고 `useCallback`이나 `useMemo`의 오남용을 체크한다.
- **App Router 활용:** Next.js App Router의 컨벤션(layout, page, loading 파일 구성 등)을 잘 따르고 있는지 확인한다.
- **타입 안정성:** TypeScript 인터페이스와 타입 정의가 명확한지, `any` 타입을 남용하지 않았는지 검토한다.

## 3. 백엔드 (Spring Boot) 지침

- **계층 구조:** Controller, Service, Repository 계층 간의 책임 분리가 명확한지 확인한다. 비즈니스 로직이 Controller에 포함되지 않도록 주의한다.
- **예외 처리:** 비즈니스 예외 상황에 대해 적절한 Exception Handling과 응답 구조를 갖추었는지 확인한다.
- **Java/Kotlin 컨벤션:** 가독성 좋은 코드 작성을 위해 변수명, 메서드명이 의도를 명확히 전달하는지 검토한다.
- **효율성:** JVM 메모리 효율을 고려한 객체 생성이나, 데이터베이스 쿼리 최적화(N+1 문제 등) 가능성을 체크한다.
- **동시성 고려:** 공유 자원에 접근하는 로직이 있다면 Thread-safe한 방식인지, 필요시 적절한 동기화나 락이 적용되었는지 확인한다.

## 4. 공통 사항

- **보안:** API Key나 비밀번호 등 민감한 정보가 코드에 노출되지 않았는지 확인한다.
- **테스트:** 로직 변경 시 테스트 코드의 작성이 필요한 부분이나, 누락된 테스트 케이스가 있다면 언급한다.
- **가독성:** 지나치게 복잡한 조건문이나 중첩 루프는 가독성을 위해 리팩토링을 제안한다.
